## 开发原则和规范初稿
### 可控性
- 尽可能减少外部依赖，选择成熟度高、社区活跃且稳定的 npm 包。

### 可读性
- 代码是给人看的，推荐使用简单易读的语法和结构。
- 保持主逻辑和流程的清晰简洁，避免过度嵌套和复杂的控制流。例如：
  - 拆分文件： 当一个文件超过150行时，考虑将其拆分成更小的文件。
  - 单一职责： 在一个函数内，避免做过多的事情，不要将不相关的逻辑放在一起，需要时适当封装。
  - 采用有意义的命名、规范的命名和注释，确保代码易于理解和维护

### 业务解耦
- 遵循高内聚、低耦合和单一职责原则，将功能模块化和组件化。

### UI 组件设计
- 实现通用和纯粹的 UI 组件，避免直接将业务逻辑混入通用组件。
- 数据归一化后传入 UI 组件，保持组件的独立性和可复用性。

### 代码质量
- 采用静态类型检查工具如 TypeScript 或 PropTypes，减少类型错误和调试时间。
- 使用代码格式化工具（如 Prettier）和代码风格指南，保持代码风格统一。
